### BUG-03：错误响应缺少业务错误码

- **现象**：登录密码错误、用户不存在、博客不存在等场景，响应体都是 `code=-1` + 一句中文文案，前端无法区分错误类型。
- **影响**：前端只能靠匹配中文文案判断错误，文案一改就失效；用户看到的提示也缺少指向性。
- **根因**：`Result.fail()` 与全局异常处理都写死 `code=-1`，项目里虽定义了 `ResultCodeEnum` 但只有 `SUCCESS/FAIL` 两个值。
- **修复**：
  1. `ResultCodeEnum` 扩展为语义化错误码（参数 1001、用户不存在 1002、密码错误 1003、重名 1004、博客不存在 1005、无权限 1006、未登录 1007、限流 1029）；
  2. `BlogException` 增加 `code` 字段，`ExceptionAdvice` 用 `Result.fail(e.getCode(), msg)` 原样透传；
  3. 23 处业务异常按语义挂码，参数校验异常（HTTP 400）统一返回 1001。
- **回归验证**：接口用例断言从 `code == -1` 升级为具体业务码，pytest 与 Java 接口测试全部通过。

### BUG-07：游客无法浏览博客列表与详情

- **现象**：不带 token 访问 `/blog/getList`、`/blog/getBlogDetail` 返回 401，未登录用户看不到任何内容。
- **影响**：博客系统的列表与详情属于公开只读内容，一刀切拦截直接劝退游客，也让首页对未登录用户完全不可用。
- **根因**：`LoginInterceptor` 用 `/blog/**` 通配拦截，没有区分读操作与写操作。
- **修复**：拦截器白名单放行 `/blog/getList`、`/blog/getBlogDetail`；发布、编辑、删除、管理端、用户接口仍需登录。
- **回归验证**：游客列表/详情返回 200，未登录调用 `/blog/add` 仍返回 401；鉴权类探针改用 `/blog/adminList`。

### BUG-08：登录接口无失败次数限制

- **现象**：同一账号可以无限次尝试密码，没有任何锁定或限流。
- **影响**：弱口令账号存在被暴力破解的风险。
- **根因**：登录方法只做密码校验，没有失败计数。
- **修复**：新增 `LoginAttemptLimiter`（内存 `ConcurrentHashMap`）——同一用户名 60 秒内最多 5 次失败，第 6 次返回业务码 1029 并提示剩余等待秒数；**成功登录清零**，只统计失败。
- **取舍**：单机内存实现，重启清零、多实例不共享；生产环境应换 Redis + 滑动窗口。
- **回归验证**：连续 5 次错误密码返回 1003，第 6 次返回 1029；另一个从未失败过的账号仍可正常登录。

### BUG-11：博客内容未做 XSS 过滤

- **现象**：正文里写入 `<script>`、`<img src=x onerror=...>`，详情页渲染时脚本被实际执行。
- **影响**：存储型 XSS，任何打开该博客的读者都会中招。
- **根因**：详情页把 `marked()` 产出的 HTML 直接 `innerHTML` 塞进页面，没有做任何过滤。
- **修复**：渲染前做白名单式消毒——先放入临时 DOM，删除 `script/iframe/object/embed/link/style/form/base/meta`，再删除所有 `on*` 事件属性与 `javascript:` 伪协议。
- **为什么不改存储**：正文是 Markdown，需要保留合法 HTML；过滤放在渲染注入点才能兼顾安全与展示。
- **回归验证**：UI-34 发一篇带 `<script>` 与 `<img onerror>` 的博客，断言正文区无 `<script>`/`onerror`、注入脚本未执行，同时 `**加粗**` 仍正常渲染成 `<strong>`。
