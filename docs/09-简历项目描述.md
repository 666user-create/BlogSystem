## 简历正文（推荐版本）

**博客系统 | 项目测试 | 2026.08-2026.09**

**项目描述**：基于 Spring Boot 3 + MyBatis-Plus + MySQL + JWT 的博客系统，包含用户注册登录、博客发布/编辑/删除（逻辑删除）、作者权限控制、管理员上下架等功能。围绕该项目完成功能测试、UI 自动化、接口自动化、抓包分析与性能测试的完整实践，并沉淀全套测试文档与三层自动化测试框架。

**相关技术**：Java、Selenium、JUnit5、Mockito、RestAssured、Postman、Python（pytest）、Fiddler（抓包分析）、JMeter、Allure、Maven、Git

- **功能测试**：基于等价类、边界值、判定表、场景法、错误推测设计 **90 条**功能测试用例，覆盖注册登录、JWT 鉴权、博客增删改查、作者权限、逻辑删除、管理员上下架等模块；首轮执行通过率 88.9%（80/90），缺陷修复回归后通过率 **94.4%（85/90）**，累计发现缺陷 **12 个**（严重 2 个、高 2 个），严重/高危缺陷修复率 100%。

- **UI 自动化**：使用 **Selenium + Java** 编写 **23 条** UI 自动化用例，覆盖登录、注册、博客发布、详情、编辑、删除、注销、权限入口共 9 个核心流程；采用 **显式等待** 替代硬休眠、**截图断言** 留存 23 张执行证据、Headless Chrome 支持 CI 运行，用例全部通过（^100%），UI 功能覆盖率 90%。

- **接口自动化**：使用 **RestAssured + JUnit5（30 条）** 与 **Python + pytest + requests（40 条）** 双技术栈实现 **70 条**接口自动化用例，覆盖 11 个接口的正常流、异常流、参数校验（400）、鉴权（401）与越权场景，**接口覆盖率 100%**；配合 **Mockito** 完成 34 条单元测试，覆盖 JWT/密码工具类与服务层业务分支（作者权限、逻辑删除、上下架）。

- **抓包与安全测试**：使用抓包代理对登录接口做抓包分析，定位 **密码明文传输风险 1 项**（生产环境需启用 HTTPS）；验证响应头无敏感字段泄露、密码不回显、SQL 注入不产生异常，相关检查已自动化为回归用例。

- **性能测试**：使用 **JMeter** 对登录、博客列表、博客详情 3 个高频接口进行 5 并发 × 10 轮压测（150 请求，含业务码断言），**吞吐量 88 请求/秒，平均响应时间 5.8ms，错误率 0%**；结合压测结果指出列表接口无分页（全量查询）为数据量增长后的首要瓶颈。

**项目链接**：https://github.com/666user-create/BlogSystem

## 面试高频追问准备

| 可能的问题 | 回答要点 |
|---|---|
| 90 条用例是怎么设计出来的？ | 从需求拆功能点（11 个接口 + 业务规则），每个功能点用等价类/边界值覆盖输入域，用判定表覆盖"角色 × 操作"权限矩阵，用场景法串联端到端流程，再用错误推测补空值/篡改/重复提交等异常 |
| 为什么同一个接口要写两套（RestAssured + pytest）？ | RestAssured 与工程同栈、能 @MockBean 替换依赖、随 `mvn test` 跑；pytest 独立于工程语言、可直接对接测试/预发环境、统一产出 Allure 报告。两套交叉验证，也对应不同公司的技术栈要求 |
| UI 自动化遇到的最大问题？ | editor.md 编辑器是异步初始化，`setMarkdown` 会报 `setValue undefined`；解决方案是等待底层 CodeMirror 就绪后调 `cm.setValue`。此外 alert/confirm 弹窗必须显式处理，否则阻塞后续操作 |
| 抓包发现了什么问题？ | 登录请求体以明文传输密码（HTTP），生产环境必须启用 HTTPS；同时验证了响应头无敏感字段、密码不回显、SQL 注入不生效 |
| 性能测试的瓶颈在哪？ | 三个接口中博客列表最慢（平均 7.3ms），因为是无分页全量查询 + DO 转换；当前数据量小不构成问题，数据量增长后会率先劣化，对应缺陷 BUG-06 |
| 你发现的最有价值的缺陷？ | BUG-04 密码明文写入日志（严重安全问题，整改为仅记录用户名）；BUG-05 JWT 密钥硬编码（改为配置化 + 环境变量覆盖）；BUG-12 参数校验异常未统一返回 400（接口契约不一致，由接口自动化发现） |
| 测试覆盖率怎么保证？ | 接口层 11/11 接口全覆盖；单元测试覆盖服务层主要业务分支（登录/注册/权限/逻辑删除/上下架）；UI 层覆盖 9 个核心流程。下一步计划接入 JaCoCo 度量代码行覆盖率 |
