## 1. 测试概述

本次测试对 BlogSystem 博客系统进行了全流程测试，覆盖需求分析、测试计划、用例设计、单元/接口/UI 自动化、缺陷跟踪与回归，验证系统功能、参数校验、鉴权与权限控制的正确性，并输出质量评估结论。

**测试目标达成情况**：
- ✅ 11 个接口功能、校验、鉴权、权限全部验证
- ✅ 核心业务流程端到端可用（注册→登录→发布→编辑→删除、管理员上下架）
- ✅ 建立自动化回归能力：JUnit5 单元测试 11 条 + Selenium UI 自动化 6 条 + Postman 接口集合
- ✅ 发现缺陷 11 条，严重/高缺陷全部修复并回归通过

### 4.4 典型缺陷说明（面试/评审重点）

1. **BUG-04 密码明文写入日志（严重）**：登录失败时日志同时打印用户输入明文密码与密码哈希。根因为 `log.warn("密码验证失败: 输入=[{}], 数据库值=[{}]", ...)` 误传敏感入参。已修复为仅记录用户名，并在代码注释中禁止再次写入。
2. **BUG-05 JWT 密钥硬编码（严重）**：签名密钥为 `public static` 字段，源码泄露即可伪造任意用户 token。已改为配置化注入（`blog.jwt.secret` + 环境变量覆盖），密钥字段私有化。
3. **BUG-01 token 头名不一致（高）**：前后端对 token 请求头命名约定不一致（`user_token` vs `userToken`）导致全部受保护接口 401。已通过"前端双写 + 后端双头兼容"修复，暴露了前后端约定管理缺失。
4. **BUG-02 写博客未鉴权（高）**：前端入口未做登录态控制且后端未强制鉴权。已通过后端拦截器强制 + 前端 401 兜底修复，前端按钮显隐控制列为后续优化。
5. **BUG-12 参数校验异常未返回 400（中）**：由接口自动化测试发现——`blogId=0` 期望 400 实际返回 200。根因为类级 `@Validated` 使 `@RequestParam` 约束校验抛出 `ConstraintViolationException`，而全局异常处理未覆盖。已补充对应 handler 统一返回 400，接口契约恢复一致。

## 7. 测试结论

**结论：通过（有条件上线）**

1. 系统核心功能（注册登录、博客 CRUD、权限控制、管理端）实现正确，全部 P0/P1 用例通过；
2. 严重与高缺陷（4 项）全部修复并回归通过，另有测试发现的中级缺陷 BUG-12 一并修复，无阻塞性问题；
3. 自动化测试资产合计 **128 条**（单元 34 + Java 接口 30 + Python 接口 40 + UI 23 + 冒烟 1），**128/128 全部通过**，可一键复现（`mvn test` / `python -m pytest`）；
4. 性能测试（JMeter）在三高频接口 5 并发下平均响应 5.8ms、吞吐量 88 请求/秒、错误率 0%，无性能阻塞；
5. 抓包分析发现登录密码明文传输风险，生产部署需启用 HTTPS；
6. 遗留 7 项风险 + 1 项抓包风险均有记录与处理建议，不阻塞当前个人使用场景。

**改进建议**：
- 接入 JaCoCo 统计代码覆盖率，目标行覆盖率 ≥ 70%；
- 列表接口增加分页（BUG-06）后重新压测，并补充 20/50 并发阶梯压测；
- 错误码体系落地（BUG-03）后统一前端提示；
- 将自动化测试（单元 + 接口 + UI 冒烟）接入 CI（GitHub Actions）持续执行。
