## 1. 测试概述

本次测试对 BlogSystem 博客系统进行了全流程测试，覆盖需求分析、测试计划、用例设计、UI 自动化、接口自动化、抓包分析与性能测试、缺陷跟踪与回归，验证系统功能、参数校验、鉴权与权限控制的正确性，并输出质量评估结论。

**测试目标达成情况**：
- ✅ 11 个接口功能、校验、鉴权、权限全部验证
- ✅ 核心业务流程端到端可用（注册→登录→发布→编辑→删除、管理员上下架）
- ✅ 建立自动化回归能力：Selenium UI 自动化 34 条 + pytest 接口自动化 47 条（含抓包与安全检查），**81/81 全部通过**

### 4.4 典型缺陷说明（面试/评审重点）

1. **BUG-04 密码明文写入日志（严重）**：登录失败时日志同时打印用户输入明文密码与密码哈希。根因为 `log.warn("密码验证失败: 输入=[{}], 数据库值=[{}]", ...)` 误传敏感入参。已修复为仅记录用户名，并在代码注释中禁止再次写入。
2. **BUG-05 JWT 密钥硬编码（严重）**：签名密钥为 `public static` 字段，源码泄露即可伪造任意用户 token。已改为配置化注入（`blog.jwt.secret` + 环境变量覆盖），密钥字段私有化。
3. **BUG-01 token 头名不一致（高）**：前后端对 token 请求头命名约定不一致（`user_token` vs `userToken`）导致全部受保护接口 401。已通过"前端双写 + 后端双头兼容"修复，暴露了前后端约定管理缺失。
4. **BUG-02 写博客未鉴权（高）**：前端入口未做登录态控制且后端未强制鉴权。已通过后端拦截器强制 + 前端 401 兜底修复，前端按钮显隐控制列为后续优化。
5. **BUG-12 参数校验异常未返回 400（中）**：由接口自动化测试发现——`blogId=0` 期望 400 实际返回 200。根因为类级 `@Validated` 使 `@RequestParam` 约束校验抛出 `ConstraintViolationException`，而全局异常处理未覆盖。已补充对应 handler 统一返回 400，接口契约恢复一致。
6. **BUG-06 列表接口无分页（中）**：代码审查发现 `getList` 全量查询。测试侧给出了量化证据——博客累积到 76 篇时 UI 自动化耗时从 50 秒劣化到 325 秒（6.5 倍）。修复为 MyBatis-Plus 分页（`pageNum/pageSize`、默认 10 条/页、`pageSize` 上限 50），前端新增翻页控件并处理空数据/越界页文案；同步补齐单元、pytest、UI 共 11 条分页用例。修复后用例数从 23 增至 32，且在数据库已有 126 篇博客的情况下耗时仅 80.4 秒——**数据量翻倍、用例变多，耗时反而降到 1/4**。
7. **BUG-14 编辑页不回显原博客（高）**：手工探索发现从详情页点"编辑"后，编辑框显示的是默认占位文本而非原文，直接提交会覆盖原博客内容——典型的"高风险静默数据损坏"。根因为未在页面加载时用 `blogId` 查询并回填，且原用例只用 JS 直接写入内容后提交，绕过了回显逻辑。已修复并补充 UI-19 回显断言。
8. **BUG-15 / BUG-17 前端展示与权限（中/低）**：详情页 Markdown 原样显示、非作者也能看到"编辑/删除"按钮。分别通过引入 `marked()` 渲染与按登录用户/作者身份控制按钮显隐修复；权限边界仍由服务端校验兜底（前端隐藏只是体验优化）。
9. **BUG-18 静态资源版本错配导致样式整体失效（中）**：由使用者反馈发现——列表页数据都在、文字都在，但卡片样式全丢，看起来"UI 被改坏了"。根因是浏览器仍用缓存的旧 `list.css`（旧选择器匹配不到分页改造后的新 DOM 层级）。修复为前端资源引用带版本号 `?v=` + 服务端静态资源 `no-cache` 条件校验。
   - **测试反思**：原有 32 条 UI 用例全部通过却没发现，因为它们只断言"元素存在/数量正确"。为此新增 UI-33 断言**计算样式**，并做了反向验证（移除 `list.css` 后该用例确实失败）。这是本次测试里最值得在面试中讲的一条"用例有效性"经验。

## 7. 测试结论

**结论：通过（有条件上线）**

1. 系统核心功能（注册登录、博客 CRUD、权限控制、管理端、列表分页、游客浏览）实现正确，全部 P0/P1 用例通过；
2. 本轮 4 条未通过用例对应的 4 个缺陷全部修复；缺陷清单累计 18 条中已修复 16 条、2 条评估保留，全量回归 **93/93 通过**；
3. 自动化测试资产合计 **81 条**（UI 自动化 34 + 接口自动化 47），**81/81 全部通过**，可一键复现（`mvnw test -Dtest=BlogUiTest` / `python -m pytest`）；
4. 性能测试（JMeter）在三高频接口 5 并发下平均响应 5.9ms、吞吐量 90.1 请求/秒、错误率 0%，无性能阻塞；
5. 抓包分析发现登录密码明文传输风险，生产部署需启用 HTTPS；
6. 仅剩 2 项**代码审查发现、无用例覆盖**的风险（BUG-09、BUG-10）+ 1 项抓包风险，均有记录与处理建议，不阻塞个人使用场景。

**改进建议**：
- 引入代码覆盖率度量（如 JaCoCo）并作为回归门禁；
- 分页已在千级数据量下验证稳定，建议造数到万级后复测深分页性能（必要时改游标分页），并补充 20/50 并发阶梯压测；
- 前端按业务错误码做差异化提示（接口已返回 1001~1029，前端目前仍展示 errMsg）；
- 将自动化测试（接口 + UI 冒烟）接入 CI（GitHub Actions）持续执行。
