### 4.4 典型缺陷说明（面试/评审重点）

1. **BUG-03 错误码未统一（中）**：所有失败响应都是 `code=-1` + 中文文案，前端只能靠匹配文案判断错误。修复为 `ResultCodeEnum` 语义化错误码（1001~1029）+ `BlogException` 携带 code + 全局异常处理透传，23 处抛异常点按语义挂码。
2. **BUG-07 拦截器一刀切（中）**：`/blog/**` 通配拦截把只读的列表、详情也挡在登录之后，未登录用户看不到任何内容。修复为白名单放行 `/blog/getList`、`/blog/getBlogDetail`，写操作与管理端仍校验登录。
3. **BUG-08 登录无限流（中）**：同一账号可无限次试密码，存在暴力破解风险。修复为同一用户名 60 秒内 5 次失败即返回 1029，成功登录清零、只统计失败；单机内存实现，生产应换 Redis + 滑动窗口。
4. **BUG-11 详情页 XSS（中）**：正文中的 `<script>`、`<img onerror>` 会被 `innerHTML` 直接执行，形成存储型 XSS。修复为渲染前白名单消毒（删脚本标签、`on*` 事件属性、`javascript:` 伪协议），并补充 UI-34 做"危险内容被剔除 + 正常 Markdown 未被误伤"的双面断言。

## 7. 测试结论

**结论：通过（有条件上线）**

1. 系统核心功能（注册登录、博客 CRUD、权限控制、管理端、列表分页、游客浏览）实现正确，全部 P0/P1 用例通过；
2. 本轮 4 条未通过用例对应的 4 个缺陷均已修复并回归，全量回归 93/93 通过；
3. 自动化测试资产合计 **81 条**（UI 自动化 34 + 接口自动化 47），**81/81 全部通过**，可一键复现（`mvnw test -Dtest=BlogUiTest` / `python -m pytest`）；
4. 性能测试（JMeter）在三高频接口 5 并发下平均响应 5.9ms、吞吐量 90.1 请求/秒、错误率 0%，无性能阻塞；
5. 抓包分析发现登录密码明文传输风险，生产部署需启用 HTTPS；
6. 仅剩 1 项抓包发现的风险（HTTP 明文传输，生产需启用 HTTPS），不阻塞个人使用场景。

**改进建议**：
- 引入代码覆盖率度量并作为回归门禁；
- 分页已在千级数据量下验证稳定，建议造数到万级后复测深分页性能（必要时改游标分页），并补充 20/50 并发阶梯压测；
- 前端按业务错误码做差异化提示（接口已返回 1001~1029，前端目前仍展示 errMsg）；
- 将自动化测试（接口 + UI 冒烟）接入 CI（GitHub Actions）持续执行。
