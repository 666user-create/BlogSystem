| 项目 | 内容 |

| 文档状态 | 已评审 |

## 1. 测试目标

1. 验证 BlogSystem 全部 11 个接口的功能正确性、参数校验、鉴权与权限控制；
2. 验证核心业务流程（注册→登录→发布→编辑→删除、管理员上下架）端到端可用；
3. 通过单元测试（JUnit5）、接口测试（Postman）、UI 自动化（Selenium）建立自动化回归能力；
4. 发现缺陷并推动修复，最终给出质量评估结论与上线建议。

## 2. 测试范围

**纳入**：
- 用户模块（注册/登录/用户信息）功能与校验
- 博客模块（列表/详情/新增/更新/删除/管理端）功能、权限与业务规则
- 鉴权机制（JWT 缺失/无效/过期/篡改）
- 管理员权限矩阵（作者/非作者/管理员/未登录 × 增删改查/上下架）
- 核心 UI 流程（Selenium 自动化 + 手工探索）
- 安全关注点（XSS、敏感信息、暴力破解风险）

**不纳入**：性能压测（仅风险提示）、代码覆盖率度量、移动端、数据库优化。

## 3. 测试策略

### 3.1 分层测试策略

| 层级 | 工具/框架 | 覆盖内容 | 执行方式 |
|---|---|---|---|
| 单元测试 | JUnit5 + Mockito | 工具类（JWT 签发/解析/篡改/过期、密码加盐哈希/校验）+ 服务层（登录分支、博客增删改查/作者权限/逻辑删除/上下架） | Maven `mvn test`，自动化 |
| 接口测试 | RestAssured + JUnit5（自动化）＋ Postman（调试） | 11 个接口的正常流、异常流、参数校验、鉴权/权限场景 | `mvn test -Dtest=*ApiTest` 自动化断言；Postman 用于日常调试与手工验证 |
| UI 自动化 | Selenium WebDriver（Java） | 注册→登录→写博客→详情→编辑→删除主流程；管理员上下架流程 | 自动化脚本 + 截图证据 |
| 手工探索 | 浏览器 + DevTools | 页面交互、边界异常、兼容性抽查 | 人工执行 |

### 3.2 测试设计方法

| 方法 | 应用场景 |
|---|---|
| 等价类划分 | 用户名/密码长度、标题长度、blogId 取值域 |
| 边界值分析 | 标题 199/200/201 字符、用户名 3/4/20/21、密码 5/6/20/21、blogId 0/1/负数 |
| 判定表 | 权限矩阵（角色 × 操作）、上下架状态流转 |
| 场景法 | 用户全流程、管理员全流程、逻辑删除流程 |
| 错误推测 | 空 token、篡改 token、重复用户名、不存在 id、空 body、超长参数 |

### 3.3 回归测试策略

- 缺陷修复后执行对应用例回归 + 关联功能冒烟；
- 每次代码变更后运行全部 JUnit5 单元测试；
- 发布前执行一次全量回归（自动化用例 + 关键手工用例）。

| 数据 | 内容 | 用途 |

## 7. 准入 / 准出标准

**准入标准**：
- 需求/接口基线已明确（01 文档评审通过）；
- 测试环境就绪（应用可启动、数据库可连接）；
- 测试数据准备完成。

**准出标准**：
- 全部 P0/P1 用例执行完毕；
- 严重、高缺陷全部修复并回归通过；中缺陷修复或评估后接受（遗留需在报告中说明）；
- 用例通过率 ≥ 90%；
- 测试总结报告输出并评审。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 博客列表无分页，造数过多影响查询 | 用例执行慢 | 控制测试数据量，另记录为缺陷 BUG-06 |
| 登录无频率限制 | 暴力破解风险 | 记录为遗留缺陷 BUG-08，报告风险提示 |
| 错误码体系未落地 | 前端提示依赖文案 | 记录为 BUG-03，报告改进建议 |
| 浏览器自动化不稳定 | 用例误报 | 关键步骤加显式等待 + 截图证据 |
