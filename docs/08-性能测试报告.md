# 08 性能测试报告（JMeter）

| 项目 | 内容 |
|---|---|
| 文档编号 | BS-TEST-DOC-08 |
| 被测系统 | BlogSystem 博客系统 v0.0.1 |
| 测试工具 | Apache JMeter 5.6.3（命令行模式）+ Java 23 / Maven |
| 测试计划 | `perf/BlogSystem-性能测试计划.jmx` |
| 原始结果 | `perf/result.jtl`、`perf/report/index.html`（JMeter Dashboard） |
| 执行日期 | 2026-08 |

## 1. 测试目标与场景选择

博客系统的访问集中在三个高频接口，按"用户使用频率"选取压测场景：

| 序号 | 场景 | 接口 | 选择理由 |
|---|---|---|---|
| 1 | 用户登录 | POST /user/login | 每次会话入口，高频且含密码校验（CPU 计算：MD5 加盐） |
| 2 | 博客列表 | GET /blog/getList | 首页加载必调，全量查询（潜在性能风险点，对应缺陷 BUG-06） |
| 3 | 博客详情 | GET /blog/getBlogDetail | 详情页必调，跨表/跨服务读取作者名 |

性能指标：**吞吐量（TPS）**、**平均响应时间**、**最大响应时间**、**错误率**。

## 2. 测试方案

```
Thread Group：5 并发线程，ramp-up 2 秒，循环 10 次
   ├── 01 POST /user/login        （JSON 断言 code=200；JSON 提取器取 token 供后续接口使用）
   ├── 02 GET  /blog/getList      （断言 code=200；提取首篇博客 id 供详情接口使用）
   └── 03 GET  /blog/getBlogDetail?blogId=${blogId}（断言 code=200）

监听器：Summary Report + 命令行 -e -o 生成 HTML Dashboard
```

- 三个请求串联为一个事务迭代，共 5 线程 × 10 轮 = **150 个请求**
- 接口依赖通过 JSON 提取器（`$.data.token`、`$.data[0].id`）串联，模拟真实用户链路
- 每个请求都带响应断言（不只看 HTTP 状态码，还校验业务码 `code=200`）

## 3. 测试环境

| 项 | 配置 |
|---|---|
| 被测应用 | Spring Boot 3.3.5，内嵌 Tomcat，端口 8080（dev profile） |
| 数据库 | MySQL 8（本机），`java_blog_spring` |
| 压测机 | 与被测应用同机（Windows 10/11，JDK 23） |
| JVM | 默认启动参数（未做调优） |

> 说明：压测机与应用同机，结果不含网络传输损耗，反映的是应用自身处理能力。

## 4. 测试结果

### 4.1 整体结果

| 指标 | 结果 |
|---|---|
| 总请求数 | 150 |
| 持续时长 | 1.7 秒 |
| **吞吐量** | **88 请求/秒**（JMeter 汇总报告 82.3/s） |
| **平均响应时间** | **5.8 ms** |
| 最小 / 最大响应时间 | 3 ms / 44 ms |
| **错误率** | **0.00%** |

### 4.2 分接口结果

| 接口 | 请求数 | 平均响应(ms) | 最小(ms) | 最大(ms) | 错误数 |
|---|---|---|---|---|---|
| 用户登录 POST /user/login | 50 | 5.0 | 3 | 44 | 0 |
| 博客列表 GET /blog/getList | 50 | 7.3 | 5 | 14 | 0 |
| 博客详情 GET /blog/getBlogDetail | 50 | 5.2 | 3 | 15 | 0 |

### 4.3 结果分析

1. **整体响应优秀**：平均 5.8ms，远低于常见接口 SLA（200ms），错误率 0%，说明在当前数据量（数十篇博客）下应用处理能力充足；
2. **博客列表最慢（7.3ms）**：列表接口无分页、全量查询且需做 DO→Response 转换，是三个接口中耗时最高的，与代码审查发现的 **BUG-06（列表无分页）** 相印证——数据量增长后此处会率先劣化；
3. **登录接口最大耗时 44ms**：为首次请求的类加载/JIT 预热（1 个请求 44ms，其余均在 3~6ms），属正常现象，非性能缺陷；
4. **详情接口稳定（3~15ms）**：依赖 `getAuthorInfo` 读取作者信息，未出现明显抖动。

## 5. 结论与建议

**结论**：当前版本在 5 并发场景下性能表现良好（吞吐量 88 请求/秒、平均 5.8ms、错误率 0），无性能阻塞问题。

**建议**：
1. **列表接口增加分页**（BUG-06）：这是数据量增长后的首要瓶颈点，建议增加 `pageNum/pageSize`，并在造数到万级后重新压测对比；
2. **补充更高并发场景**：本次为 5 并发基准测试，建议追加 20/50 并发阶梯压测，找出拐点与 TPS 上限；
3. **关注登录接口 CPU 开销**：密码为 MD5 加盐单轮计算，若后续提升为 BCrypt 等强哈希算法，需重新评估登录接口性能；
4. **引入持续性能测试**：可把本 `.jmx` 计划接入 CI 定时执行，监控接口性能回归。

## 6. 复现方式

```bash
# 1. 启动被测应用
mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 2. 执行压测（命令行模式，自动生成 HTML 报告）
jmeter -n -t perf/BlogSystem-性能测试计划.jmx -l perf/result.jtl -e -o perf/report

# 3. 查看报告
#    打开 perf/report/index.html
```

可覆盖参数：`-Jhost=127.0.0.1 -Jport=8080 -JuserName=admin -Jpassword=admin123`
