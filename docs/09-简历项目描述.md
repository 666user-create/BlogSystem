## 简历正文（推荐版本）

**博客系统 | 项目测试 | 2026.08-2026.09**

**项目描述**：基于 Spring Boot 3 + MyBatis-Plus + MySQL + JWT 的博客系统，包含用户注册登录、博客发布/编辑/删除（逻辑删除）、作者权限控制、管理员上下架等功能。围绕该项目完成功能测试、UI 自动化、接口自动化、抓包分析与性能测试的完整实践，并沉淀全套测试文档与自动化测试脚本。

**相关技术**：Java、Selenium、Postman、Python（pytest + requests）、Allure、Fiddler（抓包分析）、JMeter、Maven、Git

- **功能测试**：基于等价类、边界值、判定表、场景法、错误推测设计 **93 条**功能测试用例，覆盖注册登录、JWT 鉴权、博客增删改查、列表分页、作者权限、逻辑删除、管理员上下架等模块；首轮执行通过率 89.2%（83/93），缺陷修复回归后通过率 **95.7%（89/93）**，累计发现缺陷 **17 个**（严重 2 个、高 3 个），严重/高危缺陷修复率 100%。

- **UI 自动化**：使用 **Selenium + Java** 编写 **32 条** UI 自动化用例，覆盖登录、注册、博客发布、详情、编辑、删除、注销、权限入口共 9 个核心流程，并补充"页面数据正确性、作者操作权限、列表分页"专项用例；采用 **显式等待** 替代硬休眠、**截图断言** 留存执行证据、Headless Chrome 支持 CI 运行，用例全部通过（100%），UI 功能覆盖率 90%。

- **接口自动化**：使用 **Python + pytest + requests** 编写 **45 条**接口自动化用例，覆盖注册登录、博客增删改查、列表分页、管理端、鉴权与越权等场景，**接口覆盖率 100%（11/11）**；用例按功能模块分层组织，通过 fixture 统一管理登录态与测试数据，并集成 **Allure** 输出可视化测试报告。

- **抓包与安全测试**：使用抓包工具对登录接口做抓包分析，定位 **密码明文传输风险 1 项**（生产环境需启用 HTTPS）；验证响应头无敏感字段泄露、密码不回显、SQL 注入不产生异常，相关检查已自动化为回归用例。

- **性能测试**：使用 **JMeter** 对登录、博客列表、博客详情 3 个高频接口进行 5 并发 × 10 轮压测（150 请求，含业务码断言），**吞吐量 90.1 请求/秒，平均响应时间 5.9ms，错误率 0%**；结合压测与 UI 用例耗时数据（数据量涨到 76 篇时 UI 测试从 50 秒劣化到 325 秒）指出列表接口无分页是首要瓶颈，推动开发完成分页改造并补充 11 条分页用例。改造后列表接口最大响应从 14ms 收敛到 9ms，UI 回归在 126 篇数据下从 325 秒降到 80.4 秒。

## 面试高频追问准备

| 可能的问题 | 回答要点 |
|---|---|
| 93 条用例是怎么设计出来的？ | 从需求拆功能点（11 个接口 + 业务规则），每个功能点用等价类/边界值覆盖输入域，用判定表覆盖"角色 × 操作"权限矩阵，用场景法串联端到端流程，再用错误推测补空值、篡改、重复提交等异常 |
| Selenium 用例为什么用显式等待而不是 sleep？ | 硬休眠会让用例又慢又不稳定；显式等待（WebDriverWait）按条件轮询，元素/跳转/弹窗就绪即继续，既快又稳，也是企业自动化脚本的标准做法 |
| UI 自动化遇到过什么问题？ | editor.md 编辑器异步初始化，`setMarkdown` 报 `setValue undefined`，改为等底层 CodeMirror 就绪后 `cm.setValue`；另外原生 alert/confirm 无法被截图捕获，用"页面浮层 + 文本证据"补齐 |
| 抓包发现了什么问题？ | 登录请求体以明文传输密码（HTTP），生产环境必须启用 HTTPS；同时验证了响应头无敏感字段、密码不回显、SQL 注入不生效 |
| 性能测试的瓶颈在哪？ | 三个接口中博客列表最慢（平均 7.4ms）——它比详情接口多一次分页查询与作者信息拼装。分页改造前是全量查询，实测数据库累积到 76 篇博客时 UI 测试耗时从 50 秒劣化到 325 秒，说明该缺陷会放大为页面级性能问题；推动修复后列表接口最大响应从 14ms 收敛到 9ms，压测吞吐量从 88 提升到 90.1 请求/秒 |
| 你发现的最有价值的缺陷？ | 严重：密码明文写入日志（整改为仅记录用户名）、JWT 密钥硬编码（改为配置化 + 环境变量覆盖）；高：编辑页不回显原博客内容（直接提交会覆盖原文，属静默数据损坏）；中级：列表接口无分页（用 UI 耗时量化影响并推动改造）、参数校验异常未统一返回 400（由接口自动化发现） |
| 接口测试怎么做断言？ | 不只断言 HTTP 200，还断言业务码 `code`、`errMsg`、关键数据字段；异常场景断言 400/401 与具体错误文案；越权场景断言被拒绝且数据未被篡改 |
| 测试用例怎么保证覆盖全？ | 11 个接口 100% 覆盖；UI 层覆盖 9 个核心流程；用例与需求功能点一一映射，`docs/03-测试用例设计.md` 末尾有完整的用例统计与追溯表 |
| 分页是怎么测的？ | 接口层用 pytest 断言 pageSize 生效、越界返回空但 total 准确、非法参数 400、两页数据不重不漏；UI 层断言多页时显示翻页控件、首页禁用"上一页"、翻页后卡片不重复且能返回；单元层覆盖页数向上取整与空数据 |
