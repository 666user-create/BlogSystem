### 4.4 典型缺陷说明（面试/评审重点）

1. **BUG-04 密码明文写入日志（严重）**：登录失败时日志同时打印用户输入明文密码与密码哈希。根因为 `log.warn("密码验证失败: 输入=[{}], 数据库值=[{}]", ...)` 误传敏感入参。已修复为仅记录用户名，并在代码注释中禁止再次写入。
2. **BUG-05 JWT 密钥硬编码（严重）**：签名密钥为 `public static` 字段，源码泄露即可伪造任意用户 token。已改为配置化注入（`blog.jwt.secret` + 环境变量覆盖），密钥字段私有化。
3. **BUG-01 token 头名不一致（高）**：前后端对 token 请求头命名约定不一致（`user_token` vs `userToken`）导致全部受保护接口 401。已通过"前端双写 + 后端双头兼容"修复，暴露了前后端约定管理缺失。
4. **BUG-02 写博客未鉴权（高）**：前端入口未做登录态控制且后端未强制鉴权。已通过后端拦截器强制 + 前端 401 兜底修复，前端按钮显隐控制列为后续优化。

## 7. 测试结论

**结论：通过（有条件上线）**

1. 系统核心功能（注册登录、博客 CRUD、权限控制、管理端）实现正确，全部 P0/P1 用例通过；
2. 严重与高缺陷 4 项全部修复并回归通过，无阻塞性问题；
3. 遗留 7 项风险均记录缺陷并有明确处理建议，不阻塞当前个人使用场景；
4. 自动化回归能力已建立，建议接入 CI（GitHub Actions）持续执行单元测试与接口回归。

**改进建议**：
- 接入 JaCoCo 统计代码覆盖率，补充服务层单元测试（Mockito），目标行覆盖率 ≥ 70%；
- 补全 Postman 集合的自动化断言与 Newman 命令行回归；
- 错误码体系落地（BUG-03）后统一前端提示；
- 将 UI 自动化接入 CI 冒烟阶段。
